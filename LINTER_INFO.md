# Информация о линтере ESLint

## ❓ Что такое `npm run lint`?

**ESLint** - это инструмент для проверки качества и стиля кода JavaScript. Он **НЕ является вредоносным ПО**, а наоборот, помогает поддерживать качество кода.

## ✅ Зачем нужен линтер?

1. **Единый стиль кода** - все разработчики пишут в одном стиле (кавычки, отступы, точки с запятой)
2. **Раннее обнаружение ошибок** - находит проблемы до запуска приложения
3. **Улучшение читаемости** - код становится проще читать и поддерживать
4. **Автоматизация** - проверка выполняется автоматически при коммитах (pre-commit hooks)

## ⚠️ Проблема с Cursor IDE

Если при запуске `npm run lint` через интерфейс Cursor вы получаете ошибку:
```
ConnectError: [internal] Serialization error in aiserver.v1.StreamUnifiedChatRequestWithTools
```

**Это НЕ ошибка вашего кода!** Это внутренняя ошибка Cursor/VSCode при сериализации запроса.

## 🔧 Решения

### 1. Запуск через терминал (рекомендуется)

Откройте **PowerShell** или **CMD** в папке проекта и выполните:

```bash
npm run lint
```

Для автоматического исправления проблем:

```bash
npm run lint:fix
```

### 2. Проверка отдельных файлов

```bash
npx eslint server.js
npx eslint account_manager.js
```

### 3. Проверка через npx (если npm не работает)

```bash
npx eslint .
```

## 📋 Что проверяет линтер?

Согласно `eslint.config.js`, линтер проверяет:

- ✅ Стиль кода (кавычки, отступы, точки с запятой)
- ✅ Неиспользуемые переменные
- ✅ Использование `const` вместо `let`
- ✅ Безопасность (запрет `eval`, проверка типов)
- ✅ Соответствие правилам форматирования

## 🛡️ Безопасность кода

Ваш код **полностью безопасен**:
- ✅ Это стандартный Node.js код для работы с Telegram API
- ✅ Нет вредоносных конструкций (`eval`, `Function`, и т.д.)
- ✅ Используются только официальные библиотеки (express, telegram, nanoid)
- ✅ Все зависимости проверены через `package.json`

## 📝 Команды линтера

- `npm run lint` - проверка кода на ошибки
- `npm run lint:fix` - автоматическое исправление проблем
- `node check-lint.js` - альтернативная проверка через скрипт

## 🔍 Пример вывода линтера

При успешной проверке:
```
✅ server.js - OK
✅ account_manager.js - OK
```

При наличии ошибок:
```
❌ server.js:
  🔴 ERROR: Missing semicolon (semi)
     Строка 30, колонка 5
```

## 💡 Рекомендации

1. **Всегда запускайте линтер перед коммитом** - это поможет избежать проблем
2. **Используйте `lint:fix`** - большинство проблем исправляется автоматически
3. **Исправляйте ошибки вручную** - если автоисправление не помогло
4. **Не отключайте линтер** - он помогает поддерживать качество кода

**Важно**: Линтер - это ваш помощник, а не враг! Он помогает писать качественный код. 🚀
