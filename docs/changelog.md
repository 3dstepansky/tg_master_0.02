- **converter.js**: Конвертация данных между форматами
- **groups.js**: Работа с группами и каналами Telegram
- **parsing.js**: Парсинг данных из Telegram с безопасными задержками

## [2025-12-20] - Объяснение работы линтера и решение проблем

### Добавлено
- Создан файл `LINTER_INFO.md` с подробным объяснением работы ESLint и решениями проблем
- Документация о работе ESLint и его назначении

### Объяснение
- **ESLint** - это инструмент для проверки качества и стиля кода, а не вредоносное ПО
- Команда `npm run lint` проверяет код на соответствие правилам из `eslint.config.js`
- Ошибка `ConnectError: Serialization error` в Cursor - это внутренняя ошибка IDE, не связанная с кодом проекта
- Код проекта безопасен: это стандартный Node.js код для работы с Telegram API

### Решения проблемы с запуском линтера
1. **Через терминал напрямую**: Откройте PowerShell/CMD и выполните `npm run lint`
2. **Автоисправление**: `npm run lint:fix` - автоматически исправит большинство проблем
3. **Проверка отдельных файлов**: `npx eslint server.js` - проверка конкретного файла
4. **Прямой запуск ESLint**: `npx eslint .` - проверка всех файлов

### Зачем нужен линтер
- Единый стиль кода (кавычки, отступы, точки с запятой)
- Раннее обнаружение ошибок
- Улучшение читаемости кода
- Автоматизация проверок через pre-commit hooks

## [2025-12-20] - Создание инструкции по деплою на удаленный сервер

### Добавлено
- Создан `Dockerfile` для контейнеризации приложения
- Создан `docker-compose.yml` для оркестрации контейнеров
- Создана детальная инструкция по деплою `docs/deploy.md`
- Поддержка деплоя без создания `.env` файла (секреты через переменные окружения Docker)

### Описание изменений
- **Dockerfile**: Production-ready образ на базе Node.js 20 Alpine с оптимизацией для минимального размера
- **docker-compose.yml**: Конфигурация с volume для сессий, переменными окружения и сетевой настройкой
- **docs/deploy.md**: Пошаговая инструкция включающая:
  - Подготовку сервера и установку Docker
  - Деплой через SSH
  - Настройку переменных окружения
  - Интеграцию с n8n
  - Решение типичных проблем (400 ошибки, авторизация, классификация групп)
  - Мониторинг и логирование

### Решенные проблемы
- ✅ Ошибка 400 "TG_API_ID and TG_API_HASH required" - добавлена документация по правильной передаче в body
- ✅ Проблемы с парсингом body запросов - инструкции по использованию JSON вместо form-data
- ✅ Проблемы с авторизацией ADMIN_TOKEN - документация по настройке через переменные окружения Docker
- ✅ Проблемы с классификацией групп (NonParsing вместо parsable) - добавлен debug режим и инструкции

### Особенности деплоя
- Не требует создания `.env` файла на сервере
- Все секреты передаются через переменные окружения Docker или в теле запросов от n8n
- Volume для сессий сохраняется между перезапусками
- Поддержка debug режима для диагностики проблем
- Готовые примеры конфигурации для n8n
